# NetBuildApp マニュアル

アプリ内の「マニュアルを読む」と同じ内容です。
本文は Manual.java が原本で、このファイルは tools/build_docs.sh で生成されます。

## 1. このゲームでやること

あなたはネットワークを設計して納品する側です。

依頼者の要望を聞き、機器の構成を決め、稼働させ、起きた障害に対応します。点数がつくのは「言われたとおりに作ったか」ではなく、「聞き出せていない要望まで拾えたか」「危ない経路を残していないか」「将来足りなくなる作りにしていないか」です。

判定は決まった計算で行われます。運の要素は障害がいつ起きるかだけです。

## 2. 最初の画面

起動すると、まず選ぶ画面が出ます。

[ 案件を受ける ]
1件の案件を、要望を聞くところから納品まで。初級・中級・上級から選びます。

[ 10年の経営 ]
複数の拠点を受け持ち、10年ぶんの運用と障害対応をこなします。

[ 学習メニュー ]
マニュアルと機器の説明。用語を先に押さえておきたいときに。

[ いま使っているネットワークを見る ]
この端末の接続を調べます。

[ これまでの成績 ]
納品した案件の評価が並びます。

一度始めると、終えるまで別のモードには移れません。社員を押して「終了する」を選ぶと、確認のうえで最初の画面に戻ります。進行は保存されるので、選び直せば続きから再開できます。

## 3. 画面の見かた

常に表示されるのは4つだけです。

[ 構成図 ]
いまの設計そのものです。その案件に関係のない機器は出ません。必要になって採用したものが現れ、やめれば消えます。線の色は区画を表し、赤い破線は「本来通ってほしくないのに通ってしまう経路」を示します。障害中は原因のリンクが赤く点滅します。

[ 状態帯（上） ]
Day（経過日数）、信頼、費用、稼働状態。簡単モード中は Day の横に表示が出ます。

[ 左のキャラ ]
自社側です。押すと行動を選べます。新人と交代すると用語の解説役になります。

[ 右のキャラ ]
先方です。状況によって立つ人が変わります。押すとその人が持っている情報が読めます。

## 4. 進め方の手順

この順番で進めます。

1. 要望を聞く
   右のキャラを押します。総務担当は現場で気づいたことを、依頼者は聞かれたことに答えます。ヒントを見てから依頼者に確認すると確実です。

2. 設計する
   構成図の機器を押して切り替えます。Firewallからはルールを手で編集できます。追加・削除・順序の入れ替えができ、並び順そのものが評価されます。
   押せるのはスイッチ、Firewall、Webサーバー、社員PC、DNS、社内サーバー、プロキシ、在宅端末、保守業者です。配線を押すとその区間の説明が出ます。

3. レビューする
   社員を押して「設計をレビューする」。危険・要求未達・将来リスク・予算超過が指摘として出ます。点数もここで確認します。

4. 稼働させる
   社員を押して「翌日へ進める」。ここから先の設計変更には割増がかかります。

5. 障害に対応する
   障害が起きたら診断して原因を報告します。詳しくは第6章。

6. 直す
   設計が原因の障害は、構成を直さない限り再発率が上がります。

7. 納品する
   社員を押して「この案件を納品する」。その時点の成績が残ります。未解決の障害があると納品できません。納品後も続けられますが、成績は納品した時点のものです。

## 5. 点数の仕組み

案件適合度は4つの合計です。

[ 要求適合 ]
案件ごとに「業務上必要な通信」が決まっていて、それが通っているかを見ます。ただし、根拠となる要望を確認していないうちは加点されません。たまたま通っているのか、必要だから通したのかを区別するためです。加えて、確認できた要望1件につき加点されます。

[ 備え ]
回線が1系統だけ、バックアップが無い、といった状態は減点です。壊れないようにするのと、壊れても戻せるようにするのは別の話で、両方いります。

[ セキュリティ ]
来客から社内へ届くか、インターネットから社内へ届くか、社内サーバーが外部から触れる場所に置かれていないか。届く状態は大きな減点です。

[ 拡張性・可用性 ]
将来の利用者数に対してアドレスが足りるか。止まったら困る機器が1台しかない状態になっていないか。

[ コスト ]
予算に収まっているか。稼働後に直した場合、増えた金額の半分が割増として上乗せされます。

守りを全部入れると予算に収まりません。決裁者に増額を交渉できますが、通るのは残っているリスクを示せるときだけです。信頼が40未満では却下され、55以上なら通る額が上がります。交渉は2回まで。

納品すると評価がつきます。満点なら S、8割で A、6割で B、それ未満は C。信頼が50を切っていると1段下がります。点数だけ高くても、途中で顧客を困らせていれば評価は落ちます。

満点は設計レビューに表示されます。同じ構成でも、稼働前に決め切った場合と後から直した場合では点数が変わります。

## 6. 登場人物

[ 自社の社員（左） ]
行動の実行役。日を進める、診断する、原因を報告する、レビューする、ルールを確認する、モードを切り替える。長押しで最初からやり直せます。

[ 自社の新人（左・交代） ]
用語の解説役。VLAN、DMZ、暗黙Deny、サブネットの意味を、いまの設計の状態に合わせて説明します。

[ 依頼者（右） ]
発注担当。聞かれたことにだけ答えます。簡単モードでは助言役になります。

[ 総務担当（右） ]
未確認の要望があるときに出ます。現場で気づいたことを教えてくれます。

[ 現場担当（右） ]
障害中に出ます。症状とこれまでの診断結果を持っています。

[ 決裁者（右） ]
予算超過か信頼が下がったときに出ます。金額の説明を求められます。ここから予算の増額を交渉できます。

[ インターン（右） ]
来客セグメントから社内に届く設計のときに出ます。悪気なく私物端末をつなごうとします。

## 7. 障害と診断のやりかた

障害が起きると、原因の候補と、それぞれの確率が表示されます。

診断コマンドを1つ実行すると、結果に合う候補の確率が上がり、合わない候補が下がります。バーが1本に寄れば特定です。

[ コツ ]
ゲートウェイへのping、外部へのping、名前解決の3つは、どこまで通じているかを層ごとに切り分けます。ただしこの3つでは、IPアドレス枯渇・侵入・改ざんは区別できません。その3つはDHCP取得の確認、社内サーバーのログ、公開サーバーのログ、外部からの到達確認で初めて分かれます。

[ 報告 ]
診断回数が少ないほど信頼の上がり幅が大きくなります。外すと信頼が下がります。確率が偏るまで調べてから報告してください。

未解決のまま翌日へ進めると、そのたびに信頼が下がります。

## 8. 簡単モード

社員を押して切り替えます。

依頼者がネットワークに詳しい担当者に変わり、話しかけるたびに次にやること1つを教えてくれます。未確認の要望があれば聞くべき質問を、障害中なら次に打つ診断コマンドを、設計に足りないところがあればその項目と理由を返します。

助言のとおりに進めれば満点に届きます。ただし稼働後の変更には割増がかかるので、満点を狙うなら Day 0 のうちに聞き切って直し切ってください。

## 9. よくある失敗

[ Firewallにルールを足したのに止まらない ]
来客と社員が同じセグメントだと、通信はそもそもFirewallを通りません。分離はVLAN側の仕事です。

[ 聞かずに設計してしまう ]
将来の人数や外部公開の予定を聞かないまま作ると、要求を満たしているかどうかの判定自体ができません。加点も入りません。

[ 安く作って後から直す ]
稼働後の改修には増額分の半分が割増として乗ります。最初から入れておけば同じ構成がもっと安く手に入ります。

[ 障害を放置する ]
未解決のまま日を進めると信頼が下がり続け、決裁者が出てきます。

[ 保守用の接続を開けたままにする ]
業者が入れるということは、業者が侵害されたら攻撃者も入れるということです。必要なときだけ開ける運用にしてください。

[ 直さずに原因だけ答える ]
設計が原因の障害は、構成を直さない限り発生率が上がったままです。

## 10. 10年の経営モード

社員を押して「10年の経営を始める」で入ります。

[ 受け持つ範囲 ]
始めるときに、やさしい（1拠点）・ふつう（2拠点）・むずかしい（3拠点）から選びます。拠点が増えるほど収入も増えますが、見なければならない設備も増え、障害の起きやすさも上がります。競合の成績も規模に合わせて動きます。

[ 拠点 ]
オフィス、工場、屋外現場を受け持ちます。画面上のタブで切り替えると、図がその拠点のものになります。1か所だけで進めることもできますが、収入は増えません。

[ 初期構築 ]
自分で作り込めるのはここだけです。図を触って設計し、「稼働させる」で動かします。資金が足りなければ稼働できません。

[ カレンダー ]
「カレンダーを進める」で月が自動で流れます。障害が起きるか、更新時期が来たところで止まり、その拠点に画面が切り替わります。

[ 稼働後の判断 ]
細かい設定はもうできません。2〜3の案から選ぶ形になります。応急処置は安いが再発し、原因から直すと高いが止まります。様子を見ると費用はゼロですが、満足度が大きく下がります。

[ 障害の起きやすさ ]
設計レビューで残っている指摘の数がそのまま確率になります。危険な指摘は将来リスクの倍の重さです。更新時期を過ぎると、さらに上がっていきます。

[ BCPとサイバー攻撃 ]
回線を2系統にすると、切れても止まりません。バックアップを取っておくと、暗号化されても戻せます。備えが無い状態だと、その分だけ障害の起きやすさが上がり、起きたときの費用も跳ね上がります。バックアップ無しでランサムウェアに当たると、復旧に90万円かかり、それでも戻る保証はありません。

[ 年次点検 ]
1年ごとに点検が入り、弱点が残っていれば提案が出ます。障害が起きてから直すより安く済みますが、先送りにすると確率が高いまま次の年に入ります。

[ 更新 ]
クラウド前提の拠点は3年、自前の拠点は5年で更新時期が来ます。同等更新・拡張更新・延命の3択です。

[ 10年後 ]
儲けと満足度の2つの順位が出ます。安く済ませれば儲かりますが満足度が落ち、手厚くやりすぎると満足度は高くても儲けで負けます。

## 11. 実機の診断

ゲームで扱っている観点を、いま自分がつないでいるネットワークに当てられます。社員を押して「いま使っているネットワークを見る」から実行します。

[ 設定を見る ]
何も通信せず、端末が持っている情報を読むだけです。IPアドレス、サブネット、デフォルトゲートウェイ、DNSサーバーの台数、接続中のSSIDと電波強度が出ます。

[ 疎通も測る ]
ゲートウェイとDNSにping、名前解決、TCP接続を実際に試します。結果からゲームと同じ形で切り分けます。「IPでは届くのに名前解決だけ失敗」ならDNS側、という具合です。

[ ゲームとのつながり ]
DNSが1台しかなければ単一障害点、サブネットが狭ければ将来の台数に足りない、来客用のSSIDにつないでいれば自分が分離される側にいる。ゲームで判断したことが、そのまま目の前のネットワークの話になります。

[ この環境で出題してもらう ]
測定した実際の値から問題が作られます。ゲートウェイのアドレス、DNSの台数、サブネットの広さなど、いま目の前にある数字がそのまま問題文に入ります。環境が変われば出る問題も変わります。

SSIDを読むには位置情報の権限が要ります。取得した内容は端末の中だけで扱います。

## 12. 案件の難しさ

案件には初級・中級・上級があり、選べる項目の数が変わります。

[ 初級 ]
起業したての会社。決めることは少なく、「クラウドだけで社内に機器を置かない」か、「ファイル共有と複合機だけ置く」かのどちらかです。ここで問われるのは、要らないものを入れないことです。聞かずに一式そろえると、そのぶん無駄な出費として減点されます。

[ 中級 ]
1拠点に一通りの機器がそろいます。VLAN、DMZ、プロキシ、VPNといった判断が加わります。

[ 上級 ]
複数拠点・数千人規模。全部の条件の中から、その会社に合うものを聞き出して組み立てます。聞くべきことが7件あり、聞かないと必要なものが分かりません。

拠点が増えると、構成図が1画面に収まらなくなります。図を横にドラッグすると次の拠点に移ります。画面の下に「← 1 / 3 →」とページが出ます。ページをまたぐ配線は、端に矢印と行き先の名前で示されます。

人数が数千人になると /24（254台）では足りません。サブネットは /26 → /24 → /22 → /19 と順に切り替えられます。

[ 選べる項目 ]
社員を押して「この案件で選べる項目」を開くと、その案件で提示される項目が一覧で出ます。図に出ない設定（DHCPか固定IPか、IPv6を通すか）もここから選びます。

## 13. 案件の前提

案件によって、境界をどこに置くかが最初から決まっています。これは契約時に決まっている前提で、設計で選び直すものではありません。

[ 自前の境界 ]
拠点にFirewallを置き、そこを通して外とやりとりします。VLAN、DMZ、プロキシ、VPNといった機器の置き方が中心の判断になります。

[ クラウド境界（SASE） ]
検査をクラウド側で行い、拠点に境界を持ちません。判断の中心は「全通信を検査に通せているか」と「誰にどの資源を許すか」に移ります。機器を置く話が減るぶん、認可の設計が主役になります。

社員を押して「案件を切り替える」から選べます。進行は案件ごとに別々に保存されます。

[ 案件によって正解が違います ]
外部公開のある会社ではDMZが要りますが、外に見せるものが無い会社ではDMZは無駄な出費になります。自動生成されるルールにも、その案件では要らない許可が混ざることがあります。必要な通信を聞き出したうえで、余計な許可を消すところまでが設計です。

## 14. 機器の説明

機器ごとの役割と、置き場所の考え方をまとめてあります。まだゲームに出てこない機器（社内サーバー、クラウドサーバー、ベンダーのサーバー、VPN、プロキシ、SASE）も説明だけ読めます。

社員を押して「機器の説明を読む」から開いてください。
